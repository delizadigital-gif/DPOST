# 09 — Security, Error Handling & Testing

## 1. Security checklist (verified in Phase 16, built from Phase 1)

| Area             | Control                                                                                                                                                                           |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Passwords        | Argon2id. Never logged. Reset revokes all sessions                                                                                                                                |
| Sessions         | HttpOnly + Secure + SameSite=Lax cookies. Rotation on login and privilege change. Server-side revocation                                                                          |
| CSRF             | SameSite + `Origin` check on all mutating routes. Server Actions' built-in origin check                                                                                           |
| XSS              | React escaping. **No `dangerouslySetInnerHTML`** for user or AI content (lint rule). Strict CSP with nonces. AI output rendered as text or sanitized markdown (limited allowlist) |
| SQL injection    | Prisma parameterization. `$queryRaw` only with tagged templates. `$queryRawUnsafe` banned via lint                                                                                |
| Tenant isolation | Service-layer ctx + tenant-guarded Prisma client + isolation test suite. 404 on foreign IDs                                                                                       |
| Authorization    | Role → permission policy checked in every service. Admin routes need `platformRole` + recent re-auth                                                                              |
| Secrets          | Env only, zod-validated at boot, never `NEXT_PUBLIC_`. Separate secrets per environment                                                                                           |
| Social tokens    | AES-256-GCM with key versioning. Decrypted only at use. Logger redaction. Never serialized to API responses (response DTOs whitelist fields)                                      |
| OAuth            | Random single-use `state` bound to user and workspace. Exact redirect URI match. Code exchanged server-side only                                                                  |
| AI actions       | Tool allowlist per role. Zod validation. Signed single-use confirmation tokens. `maxSteps`. Audit trail                                                                           |
| Prompt injection | Untrusted content wrapped as data. No tool can exfiltrate to arbitrary URLs. Destructive tools always require a user click                                                        |
| Uploads          | Presigned PUT with size/type conditions. Magic-byte sniffing. Re-encode via sharp. EXIF strip. Private bucket + signed GETs. Per-workspace key prefix                             |
| Webhooks         | HMAC verification with the raw body before parsing. Constant-time compare. Event-ID dedupe. Fast 200 + async work                                                                 |
| Rate limiting    | Redis buckets per IP / user / workspace / channel (see [04](04-api-architecture.md))                                                                                              |
| Headers          | HSTS, CSP, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `frame-ancestors 'none'`                                                                            |
| Dependencies     | Lockfile. Renovate/Dependabot. `pnpm audit` in CI                                                                                                                                 |
| Audit logs       | All mutations by user, agent, admin: deletes, schedules, publishes, connections, plan changes, admin actions                                                                      |
| Backups          | Daily managed Postgres backups + PITR where available. Quarterly restore drill                                                                                                    |
| Privacy          | Data minimization. Deletion flows (user + Meta callback). PII scrubbing in Sentry. Bangladesh's data protection rules to be reviewed with counsel before launch                   |

## 2. Error handling matrix

| Failure                          | Detection                                  | System behavior                                                                                                                                          | User sees                                                                                                     |
| -------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Facebook token expired/revoked   | Error 190 / token-health job               | Channel → `needs_reconnect`. Pending publications for that channel stay `scheduled` but are pre-flagged. Publish attempts fail as `AUTH` without retries | Red banner + email: "Reconnect _Rahim's Kitchen_ so your 6 scheduled posts can go out." One-click Reconnect   |
| Facebook rate limit              | Error codes / usage headers                | Backoff. Analytics throttled first                                                                                                                       | Nothing unless the publish is delayed by more than 10 min: "Facebook is busy, your post will go out shortly." |
| Facebook 5xx / timeout           | HTTP status                                | 3 retries (1 / 5 / 15 min)                                                                                                                               | If all fail: post marked Failed with a Retry button + notification                                            |
| Content rejected by Facebook     | `PERMANENT` class                          | No retry. Stores the reason                                                                                                                              | "Facebook rejected this post: _image too large_. Edit and retry."                                             |
| OAuth cancelled / denied         | Callback `error` param                     | Nothing stored                                                                                                                                           | "Connection cancelled. You can connect any time from Channels."                                               |
| OAuth user has no Pages          | Empty `/me/accounts`                       | —                                                                                                                                                        | Guided help: "You need to be an admin of a Facebook Page," with a link to Meta's help on creating a Page      |
| LLM API error / timeout          | SDK errors                                 | Retry once with backoff. Optional fallback provider. For plans, per-batch retry with partial results kept                                                | "The AI is having a moment. Try again." Plans: "12 of 14 done, [Retry the rest]"                              |
| LLM invalid output               | Zod parse failure                          | One repair attempt ("fix to match schema"), then regenerate                                                                                              | Invisible unless it keeps failing                                                                             |
| Image provider refusal / failure | Provider error                             | No quota charged on failure                                                                                                                              | "Couldn't create that image. Try describing it differently."                                                  |
| Quota exceeded                   | Pre-check                                  | Blocked before any spend                                                                                                                                 | "You've used 30/30 AI posts this month," with an upgrade option                                               |
| Database unavailable             | Prisma connection error                    | Health check fails. Worker pauses queues (jobs are retried, not lost)                                                                                    | Generic error page with retry. Status noted in admin                                                          |
| Redis unavailable                | Connection error                           | Web keeps working for reads. Scheduling mutations fail safely (the transaction rolls back). Reconcile re-enqueues everything on recovery                 | "Scheduling is temporarily unavailable" on schedule actions only                                              |
| Worker down                      | Heartbeat missing more than 2 min          | Alert (Sentry/uptime). Reconcile catches up on restart                                                                                                   | Late posts publish on recovery. Admin sees a stale heartbeat                                                  |
| Stuck `publishing` state         | Sweeper: `publishing` for more than 10 min | Check the Page for the post before retrying (duplicate guard)                                                                                            | Resolved automatically, or marked Failed                                                                      |

**Rule:** users see a plain-language message + an action + a request ID under "Details". Stack traces go only to Sentry and logs.

## 3. Testing strategy

**Priority order** (where bugs cost money, trust or data): tenant isolation → auth → publishing correctness → AI tool authorization/confirmation → quotas/billing → everything else.

| Layer                              | Tooling                                   | What                                                                                                                                                                    | Target                                                                         |
| ---------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Unit                               | Vitest                                    | Pure logic: slot allocator (property-based via fast-check), status machines, quality gate, brand card renderer, error classifier, crypto, validators, metric normalizer | Fast (< 10 s total), ~90% on `core/` logic modules                             |
| Service/integration                | Vitest + Testcontainers (Postgres, Redis) | Services against a real DB: CRUD, transitions, quotas, audit writes, queue enqueue/dequeue                                                                              | Every service function                                                         |
| Isolation suite                    | Vitest                                    | Generated: for every service, route and AI tool, workspace A cannot read or mutate workspace B's resources                                                              | 100% of tenant-scoped endpoints/tools (fails CI if a new route lacks coverage) |
| API                                | Vitest + route handler invocation         | Status codes, error shape, validation, auth levels, rate limits                                                                                                         | All `/api/v1` routes                                                           |
| Social adapter                     | MSW with recorded Graph fixtures          | Success paths, each error class, pagination, header parsing                                                                                                             | All adapter methods                                                            |
| Worker                             | Vitest + Testcontainers                   | Publish exactly-once under concurrency, retries, permanent failures, reschedule job swap, reconcile after Redis flush, stuck-publishing sweeper                         | All processors                                                                 |
| AI pipelines                       | Mock LLM (scripted responses)             | Pipeline control flow, repair, partial failures, metering                                                                                                               | All pipelines                                                                  |
| Agent                              | Scripted fake model emitting tool calls   | Tool selection, confirmation required/honored, token replay/tamper/expiry rejected, maxSteps, error surfacing                                                           | Every tool + 10 scenario scripts                                               |
| AI quality (eval, not CI-blocking) | Script + real API                         | Golden-set briefs: schema validity, language accuracy, duplicate rate, invented facts, judge scores                                                                     | Run per prompt change; results logged                                          |
| E2E                                | Playwright                                | Sign-up → verify → onboarding; generate → approve → schedule (mock social); chat command → confirm → calendar updates; failed publish → retry; mobile viewport smoke    | ~10 critical flows, on every PR against a preview environment                  |
| Live smoke                         | Manual checklist                          | Real Facebook test Page publish (text, image, multi-image)                                                                                                              | Before each production release                                                 |
| Accessibility                      | axe (Playwright)                          | Shell, composer, calendar, chat, dialogs                                                                                                                                | Zero serious violations                                                        |
| Performance                        | Lighthouse CI, k6 (Phase 16)              | Landing LCP; publish burst of 500 posts/min                                                                                                                             | Budgets in the roadmap                                                         |
